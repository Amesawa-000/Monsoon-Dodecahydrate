# reduce-ai-slop

写作与改写 skill：去掉文字里的"AI 味"——套话、模板结构、均衡到发平的句长、空泛收尾——同时保住原意、文体和作者本来的声音。

## 它解决什么问题

读者一眼能感到的"像机器写的"，通常不是某个词的问题，而是几层习惯叠在一起：

| 层 | 表现 |
| --- | --- |
| 词语 | 抽象判断多、能核实的事实少；万能动词与黑话（赋能、助力、抓手、闭环）；形容词密集却没有对象 |
| 句子 | 句长均匀、结构一致，没有停顿与轻重；对偶句反复出现（不仅……更……、不是……而是……） |
| 结构 | 空泛时代开场 → 首先、其次、再次 → 重复结论；硬凑三点，段落与小标题对称 |
| 声音 | 对谁说都一样；情绪靠标签宣告；过分圆滑；结尾习惯性升华、号召、展望 |

skill 的原则是：**不找更漂亮的同义词，先找事实、动作、对象、因果，或者干脆删句。**

## 特点

- **诊断看模式，不是抓单词。** 禁词表是候选，不是机械删除清单；术语在专业文本里应当保留。
- **分文体处理。** 学术、商务邮件、社交媒体、个人叙事、说明文、翻译各有取舍，不把严谨改成聊天腔。
- **三档强度。** 轻度（去套话）/ 中度（默认）/ 重写；不擅自改立场、事实与文体。
- **分层优先。** 事实与用户要求 > 文体与声音 > 清楚具体有节奏 > 个人化修饰。
- **有底线。** 不编造数据与经历，不冒充亲历，不承诺绕过 AI 检测，不仿写在世作者的可识别风格。

## 使用方式

在 DSH 中由 `description` / `whenToUse` 触发，也可直接调用：

```
skill: reduce-ai-slop
```

常见触发语：去 AI 味、不像人写的、太官方、太模板、写得像真人、humanize this。

`SKILL.md` 内含：目标与边界、诊断四类信号、中英套话候选词表、改写流程八步、分文体处理、三档强度、诚实与安全边界、交付前检查清单。

## 安装

skill 是一个目录，入口文件为 `SKILL.md`（YAML frontmatter 需含 `name` 与 `description`，`name` 使用 kebab-case）。放进下列任一扫描根即可：

| 位置 | 说明 |
| --- | --- |
| `<DSH_HOME>/skills/` | 用户级（`DSH_HOME` 默认为当前用户主目录下的 `.dsh`） |
| `<项目>/.dsh/skills/` | 项目级，优先级更高 |
| `<项目>/.agents/skills/` | 项目级 |

DSH 的 skill 目录默认开启热加载，复制进去后无需重启。验证：在 skill 目录里能看到 `reduce-ai-slop`，或用 `skill` 工具加载。

```
<DSH_HOME>/skills/reduce-ai-slop\
├── SKILL.md
└── README.md
```
