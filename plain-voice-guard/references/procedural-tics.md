# B 族词表：工程流程 / 术语洪水

所属族：B（GPT 系文字任务常见）。姊妹词表：[affect-tics.md](affect-tics.md)（A 族，DeepSeek 系）、[hedge-tics.md](hedge-tics.md)（C 族，GPT 系）、[drama-tics.md](drama-tics.md)（D 族，Gemini 系）。

来源：用户提供的梗图（标注为 GPT 系列模型的 AI 化表达）。原文：

> 你说得对，但我要开始核验、检索、探针、检查、审计、评估、冻结、快照、哈希、夹具、门禁和回滚了。
> 我先明确目标、约束、边界和验收，核对事实与证据，建立唯一基线，记录指纹，完成备份与恢复演练；再拆解、验证。核对与实际差异，检查异常和副作用，再静态、单元、集成、回归、冒烟、安全检查、性能验证和故障注入，逐项确认全部门禁通过。还要 dry-run，校验依赖、权限、一致性；先灰度，再放量，发现异常立即回滚，最后跑验收矩阵，复核，将变更、证据链、异常处理和结论统一归档。

## 毛病在哪

不是术语错，是**术语与对象脱钩**：十三个动作没有一个说明作用在什么东西上，也说不出结果。流程词在这里的功能是制造"严谨""专业"的观感，不是传递信息。

第二个毛病是**宣言代替动作**："我先明确目标、约束、边界和验收""我要开始……了"。真做事的人不会先宣布自己要严谨。

第三个是**清单过密**：静态、单元、集成、回归、冒烟、安全、性能、故障注入排成一串，读者无法判断哪些真跑了、结果如何、哪些没测。

## 词表

**测试与验证**：核验、校验、验证、复核、审计、评估、探针、检查、筛查、排查、抽检、验收矩阵、门禁、dry-run、冒烟、回归、集成、单元、静态、性能验证、故障注入

**状态与安全**：冻结、快照、哈希、指纹、基线、唯一基线、备份、恢复演练、回滚、灰度、放量、证据链、归档、留痕、可追溯

**工程对象**：夹具、依赖、权限、一致性、副作用、异常、变更、影响面、边界、约束、目标、验收标准

**宣言句式**：我要开始……了 / 我先明确…… / 系统性地…… / 完成一次完整的…… / 逐项确认全部……通过 / 统一归档

单个词都是正常术语，成串出现且缺少对象与结果时才是腔调。

## 改法

一个动作 → 一个对象 → 一个结果。三步都写不出，这个动作就是编的。

| 腔调 | 改法 |
| --- | --- |
| 我要开始核验、检索、检查、审计了 | 我先看了 A、B 两处 |
| 建立唯一基线 | 记下现在能跑通的状态 |
| 静态、单元、集成、回归、冒烟全部通过 | 跑了单元和集成测试，9 个用例全过；冒烟没做 |
| 完成备份与恢复演练 | 备份了数据库，恢复演练没做 |
| 先灰度，再放量 | 先放 10% 流量，明早看错误率再决定 |
| 逐项确认全部门禁通过 | 构建和测试门禁过了，代码评审还没过 |
| 将变更、证据链、异常处理和结论统一归档 | 变更记录写在 PR 描述里 |

**示例改写**（示意，不是真实记录）

> 改写：我先备份数据库，再跑单元、集成和回归测试，构建和冒烟也过，性能没测。发现问题能回滚。现在灰度 10% 流量，明早看异常再决定放量。

保留了什么：对象（数据库、测试、构建、流量）、顺序、结果、未测项。删掉了什么：宣言、术语堆、没有对象的动作。

## 反例：合法用法

- 用户是开发者，问的确实是发布流程 → "先灰度再放量"是必要信息，保留。
- 术语是全篇的技术共同语（写 CI 文档、SRE 复盘）→ 保留密度，只需补对象和结果。
- 用户要求"按检查清单逐项确认" → 清单本身是交付物，不要打散。
- 真实的不确定与未做项必须写明，不能为了干净把"没测"删掉。

判据仍是那句：这句在交付内容，还是在展示严谨。
